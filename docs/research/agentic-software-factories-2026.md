# Harden the Builder, narrow the merge gate

Guild's shape matches what leading teams converged on in 2025-2026: one writing agent per task inside a deterministic harness that owns every side effect, read-only agents that add judgement rather than actions, quarantined triage whose writes go through a job with no model, small tasks, capped retries, a fresh-context reviewer and a provider-enforced spending limit. Stripe, Spotify, GitHub's Agentic Workflows and Copilot agent, Cognition and Anthropic's own harnesses all landed there. Three things need to change before Guild runs unattended. First, **T0 auto-merge of code goes past every published precedent**: no major open-source policy and no large engineering organisation lets agent-written code merge without a human, independent maintainers would reject about half of agent patches that pass their tests, and AI reviewers rarely find anything in the small diffs a library produces, so T0 should cover documentation only and stay in shadow until a count of clean decisions, not a calendar, justifies it. Second, **the published incidents point at the Builder and CI, not triage**: agent-written `conftest.py`, `pyproject.toml` and pre-commit hooks execute in CI, headless Claude Code loads the checkout's configuration without a trust prompt, and the Actions cache ignores `permissions:` boundaries, so the Builder should hold no token and agent branches should never run where a secret lives. Third, **the controls Guild treats as hard are soft**: `--max-budget-usd` is a client-side estimate checked between turns, a single-trial drill cannot see a regression smaller than the 6-point swing that infrastructure alone causes, and Anthropic's own evals missed three Claude Code harness regressions in spring 2026. Almost every operational number in this field is a vendor reporting on itself. The independent studies (METR, MAST, the AIDev papers, the reviewer-habituation work) agree on direction but not magnitude, and nothing independent has tested a Guild-like pipeline on real library maintenance, so confusable's own ledger and drills will be the evidence that settles its open questions.

## Leading teams run one writer inside a deterministic shell

The clearest pattern in 2025-2026 practice is that the agent is the smallest part of the system. Stripe's Minions merge **more than 1,000 fully agent-written PRs a week**, but each run sits in a devbox "cut off from production resources and the internet", deterministic code handles git, lint and tests "so required steps always run", a run gets **at most two CI rounds**, and every PR "must pass CI and be reviewed by another Stripe engineer before merging" ([Stripe](https://stripe.dev/blog/minions-stripes-one-shot-end-to-end-coding-agents)). Spotify's Honk agent may only edit files and call verifiers; pushing, messaging and prompt authoring belong to the surrounding infrastructure, and verifiers run in a Claude Code stop hook so a failing change never becomes a PR ([Spotify](https://engineering.atspotify.com/2025/12/feedback-loops-background-coding-agents-part-3)). GitHub built the same split into its products: the Copilot cloud agent pushes to one branch, cannot approve or merge, and its CI waits for a human to click "Approve and run workflows" ([GitHub Docs](https://docs.github.com/en/copilot/concepts/agents/coding-agent/risks-and-mitigations)), while Agentic Workflows run the agent read-only and apply its writes in a separate job after deterministic checks ([GitHub](https://github.blog/ai-and-ml/generative-ai/under-the-hood-security-architecture-of-github-agentic-workflows/)). Anthropic's closest analogue to Guild, a planner, a generator and a separate evaluator that talk through files, exists because agents "reliably skew positive when grading their own work"; it cost **over 20x a solo run ($200 against $9)** for a clearly better result ([Anthropic](https://www.anthropic.com/engineering/harness-design-long-running-apps)). All of these are vendors describing their own systems, but they describe the same architecture.

Independent and multi-vendor research explains why a single writer wins. Google's study of 180 configurations across GPT, Gemini and Claude found that every multi-agent variant **degraded a sequential planning task by 39-70%**, and that independent agents amplified errors 17.2x against 4.4x for centrally coordinated ones; it included no coding benchmark ([Google Research](https://research.google/blog/towards-a-science-of-scaling-agent-systems-when-and-why-agent-systems-work/)). MAST's annotation of 1,642 traces from seven open-source multi-agent frameworks found **failure rates of 41-86.7%**, dominated by step repetition, ignored termination conditions, disobeyed specifications and missing verification; better role prompts recovered only 9.4% and an objective verification step 15.6% ([MAST](https://arxiv.org/html/2503.13657v3)). Cognition, which argued against multi-agent systems in 2025, now reports that what works is systems where "writes stay single-threaded and the additional agents contribute intelligence rather than actions" ([Cognition](https://cognition.com/blog/multi-agents-working)). Guild's sequential, centrally orchestrated chain with one Builder per issue sits on the safe side of all three. Two of its roles have no supporting evidence as agents: nothing shows Triage or Releaser gaining from being more than a deterministic script with one bounded model call. The Planner's value over good acceptance criteria is also unmeasured, and a 2026 benchmark analysis attributes the largest share of agent failures to requirement clarification rather than planning ([SWE-RPG](https://arxiv.org/pdf/2608.09072), read through a secondary summary). That argues for spending the Planner's effort on checkable acceptance criteria and a "needs clarification" exit back to the steward, and for a "sprint contract", as in Anthropic's harness, in which Planner and Reviewer fix the acceptance checks before the Builder starts.

Guild departs from the pattern on token placement. It gives roles their own GitHub Apps, while Stripe, Spotify and GitHub keep the write credential in the deterministic wrapper and let the agent return a diff or a structured request. The most detailed public record of agent PRs in a mature repository also shows how close humans stay. In dotnet/runtime the Copilot agent opened 878 PRs in ten months; **67.9% merged, with a 0.6% revert rate against 0.8% for other PRs**, but a maintainer requested every one, every PR got human review, and humans pushed commits to 52% of the merged PRs, which succeeded 86.2% of the time against 55.1% without human commits ([Toub](https://devblogs.microsoft.com/dotnet/ten-months-with-cca-in-dotnet-runtime/)). Adding an instructions file lifted success from about 38% to 69%, changes of 1-50 lines did best (76-80%), and one maintainer opening nine PRs from a phone created an estimated five to nine hours of review. For Guild this supports the investment in AGENTS.md and small diffs, argues for letting stewards push commits onto agent PRs, and warns that three stewards can be swamped by their own agents.

The plugin-and-charter packaging of pillar 1 fits the tooling, with caveats the docs make explicit. Subagents supplied by a plugin ignore their `hooks`, `mcpServers` and `permissionMode` settings, so Guild is right to keep role files in each repository's `.claude/agents/`; a repo-level agent silently shadows a plugin agent of the same name, and an environment variable can force every subagent's model over its frontmatter ([Claude Code subagents](https://code.claude.com/docs/en/sub-agents)). Every enabled plugin's skill and agent descriptions sit in context on every turn ([plugins](https://code.claude.com/docs/en/plugins)), and Anthropic's own guidance warns that "Bloated CLAUDE.md files cause Claude to ignore your actual instructions" ([best practices](https://code.claude.com/docs/en/best-practices)); OpenAI's agent-only team keeps AGENTS.md to a roughly 100-line table of contents ([Latent Space](https://latent.space/p/harness-eng)). Numbered charter clauses have a direct precedent in Spec Kit's constitution, which is enforced through "Phase -1" gates that make each plan check every article and justify exceptions in writing ([Spec Kit](https://github.com/github/spec-kit/blob/main/spec-driven.md)), though no study shows such files improve outcomes, and Thoughtworks' independent review found agents sometimes ignoring them and the human reviewer buried in generated Markdown ("I'd rather review code than all these markdown files") ([Böckeler](https://www.martinfowler.com/articles/exploring-gen-ai/sdd-3-tools.html)). The charter earns its keep at enforcement points, not by being read. Every harness above also shed parts as models improved: Anthropic removed its sprint construct with Opus 4.6, concluding that "every component in a harness encodes an assumption about what the model can't do on its own" ([Anthropic](https://www.anthropic.com/engineering/harness-design-long-running-apps)), and Spotify's LLM judge, which vetoed about a quarter of sessions in December 2025, was removed by March 2026 as "too rigid" ([InfoQ](https://www.infoq.com/news/2026/03/spotify-honk-rewrite/)). Guild's plugin should record, next to each role and gate, the assumption it encodes and the drill that would show it is no longer needed.

## Independent studies set the direction while vendors supply the numbers

The evidence base splits cleanly. Independent work (academic studies, METR, mining studies of public GitHub data, security researchers backed by primary advisories) establishes what goes wrong and in which direction. Vendors and adopting companies supply nearly all the throughput, cost and success figures, define their own denominators, and rarely publish failures. Where both exist for the same product they diverge: Cognition reports 67% of Devin PRs merged ([Cognition](https://cognition.com/blog/devin-annual-performance-review-2025)), while an independent MSR 2026 study of 2,252 Devin PRs found 61.6% ([arXiv 2602.08915](https://arxiv.org/html/2602.08915)).

Four gaps matter most for Guild. No independent study compares a role-separated pipeline with a single agent on real repository maintenance; Google's study had no coding task and MAST's coding systems are 2023 designs. No one has published a defect or revert rate for agent PRs merged with only an AI approval in an open-source library; the nearest figures are Vercel's two reverts in 513 monorepo PRs merged without human review, from a vendor page that returned HTTP 404 when the researchers fetched it ([Vercel](https://vercel.com/blog/58-percent-of-prs-in-our-largest-monorepo-merge-without-human-review)), and dotnet's 0.6%, which had human review. The cross-model review result rests on one preliminary single-author preprint. And there is no measured precedent for how long a shadow phase must run. The security evidence is in better shape than the productivity evidence: the researchers often sell security products, but their incidents are backed by GHSA advisories, CVE numbers and vendor fixes.

## Incidents hit the agents that hold tokens, not the ones that read

Every 2025-2026 compromise of an AI agent in CI followed one pattern: attacker-writable GitHub text reached a model that shared a runtime with secrets, a shell or a write path, and data left through a side channel. In PromptPwnd, Google's own gemini-cli triage workflow passed issue text to an agent holding a read-write `GITHUB_TOKEN` and cloud keys; hidden instructions made it run `gh issue edit` with the secrets in the body, and Aikido found that with Claude Code Action opened to non-write users a privileged token "could almost always be leaked", even without prompt interpolation, because the agent fetched the malicious text itself ([Aikido](https://www.aikido.dev/blog/promptpwnd-github-actions-ai-agents)). Comment and Control, public in April 2026, made Anthropic's security-review action, Gemini CLI's action and the Copilot agent leak API keys and tokens into PR comments and logs, with the Copilot payload base64-encoded to slip past secret scanning ([SecurityWeek](https://www.securityweek.com/claude-code-gemini-cli-github-copilot-agents-vulnerable-to-prompt-injection-via-comments/)). **Guild's quarantined triage defeats the commonest version of this attack**: a model with no tools and no write token cannot edit the issue, and a job without a model that posts only from a validated record has nothing to obey. That is GitHub's "safe outputs" design, the quarantined half of DeepMind's CaMeL ([arXiv 2503.18813](https://arxiv.org/pdf/2503.18813)), and compliant with Meta's Rule of Two, under which one session should combine no more than two of untrusted input, sensitive access and external state change ([Meta](https://ai.meta.com/blog/practical-ai-agent-security/)).

The incidents also show what the quarantine leaves open. Clinejection began with a plain-ASCII issue title in Cline's Claude triage workflow, which had been opened to all users with shell and write tools. The injected agent installed a package that flooded the Actions cache past 10 GB to evict legitimate entries, then planted entries matching the nightly release job's cache key; the release job restored them and exposed the VS Code Marketplace, Open VSX and npm publish tokens, and an unknown actor later published a malicious `cline@2.3.0` ([Adnan Khan](https://adnanthekhan.com/posts/clinejection/)). The lesson is that "any workflow can read from and write to the cache" whatever its `permissions:` block says, and issue-triggered jobs share the default branch's cache scope with release jobs. Egress allowlists leak too: **CVE-2026-54316 leaked an API key one character at a time through download counters on 64 attacker repositories on huggingface.co**, a domain Claude Code's web fetch had pre-approved ([GHSA-fg94-h982-f3mm](https://github.com/anthropics/claude-code/security/advisories/GHSA-fg94-h982-f3mm)), and an earlier advisory covered DNS exfiltration through pre-approved `ping` and `dig` ([GHSA-x5gv-jw7f-j6xj](https://github.com/anthropics/claude-code/security/advisories/GHSA-x5gv-jw7f-j6xj)). CamoLeak exfiltrated private code through one signed image-proxy URL per character in rendered Markdown, which GitHub fixed by switching off image rendering in Copilot Chat ([Legit Security](https://www.legitsecurity.com/blog/camoleak-critical-github-copilot-vulnerability-leaks-private-source-code)). For Guild this means a triage step with no tools at all (ideally a plain model API call rather than the agentic CLI), no package installs in issue-triggered jobs, egress limited to the model endpoint, the model credential kept out of the process environment where possible, and a record schema of closed enums whose comments come from fixed templates with no URLs, mentions, images or model free text.

Escaping all non-ASCII is a recognised mitigation in narrower forms. AWS recommends stripping Tag-block characters (U+E0000 to U+E007F) before the model and shows how easily a strip filter goes wrong, including a bug in its own first sample ([AWS](https://aws.amazon.com/blogs/security/defending-llm-applications-against-unicode-character-smuggling/)); claude-code-action strips invisible characters, HTML comments, entities and image alt text ([claude-code-action security.md](https://github.com/anthropics/claude-code-action/blob/main/docs/security.md)); the Copilot agent filters hidden characters. Escaping beats stripping for confusable, because its bug reports legitimately contain the invisible and look-alike characters the stewards need to see, and confusable's own detectors can annotate the record with which code points are invisible, bidirectional or Tag-block, so a steward sees an attack rather than losing it. But the real attacks were mostly plain ASCII: issue prose in PromptPwnd, the title in Clinejection, `$(...)` in Nx, HTML comments in CamoLeak. HTML numeric entities are ASCII and decode to bidi or Tag characters later. An escaped Tag run is a trivial cipher (ASCII plus 0xE0000), so an ASCII preamble can ask the model to decode it; no published study measures whether frontier models will. And a JSON hop silently undoes backslash-u escapes, because a conforming parser decodes them ([RFC 8259](https://www.rfc-editor.org/rfc/rfc8259#section-7)); confusable's own `AGENTS.md` already warns that such an escape in a tool parameter can reach a file as the literal character. Guild should convert issue Markdown to plain text, drop comments and entities, escape into a notation JSON never interprets (`U+202E`), and treat escaping as hygiene beneath the architecture rather than a boundary. No vendor that filters characters claims it is sufficient, and Willison's verdict that a guardrail stopping 95% of attacks is "a failing grade" applies ([Willison](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/)).

The larger exposure is the Builder and the CI it triggers. A headless `-p` session shows neither the workspace-trust prompt nor the `.mcp.json` approval prompt ([Claude Code security docs](https://code.claude.com/docs/en/security)), so whatever `.claude/settings.json`, hooks, `.mcp.json`, CLAUDE.md and AGENTS.md sit in the checkout are loaded. **Claude Code's advisory feed lists flaws of exactly this class roughly monthly through October 2026**, among them command execution before the trust dialog, a trust bypass through a repository settings file, a sandbox escape through `settings.json`, a malicious `git` on the search path (13 October) and a bypass of plugin commit-SHA pins (9 October) ([advisories](https://github.com/anthropics/claude-code/security/advisories)). claude-code-action executed a PR's `.mcp.json` until version 1.0.74 ([GHSA-8q5r-mmjf-575q](https://github.com/anthropics/claude-code-action/security/advisories/GHSA-8q5r-mmjf-575q)), and Gemini CLI's headless mode auto-trusted `.gemini/` configuration and `.env` ([GHSA-wpqr-6v78-jr5g](https://github.com/google-github-actions/run-gemini-cli/security/advisories/GHSA-wpqr-6v78-jr5g)). The action now restores `.claude/`, `.mcp.json`, CLAUDE.md and `.husky/` from the base branch but leaves `package.json`, lockfiles, Makefiles and linter configuration at the PR head. In this repository the equivalents are `pyproject.toml`, `uv.lock`, `conftest.py`, `tests/**`, `tools/**` and `.pre-commit-config.yaml`, which pre-commit uses to fetch and run hook code. Guild's missing `workflows` permission protects `.github/workflows/`, and probably not composite actions, CODEOWNERS or `dependabot.yml` (unverified). Pushes made with an App token trigger CI, unlike `GITHUB_TOKEN` pushes ([Claude Code GitHub Actions docs](https://code.claude.com/docs/en/github-actions)), so agent-written code will execute in CI unless Guild designs against it; GitHub's own answer is to treat agent code as outside-contributor code whose workflows wait for a human. In Rule of Two terms the Builder already holds sensitive access and state change, so it must never also read untrusted input: no raw issue text, no outsider comments, no web, only the validated record and a steward-approved plan. The Reviewer is a target as well, because it reads text the Builder wrote; OpenAI's Codex was caught when one agent pass wrote attacker content into AGENTS.md that a second pass loaded as instructions ([CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-ai-coding-agent-ci-prompt-injection-202608/), secondary).

The release path has the longest incident list and the most settled fixes. Nx's s1ngularity compromise came from a `pull_request_target` workflow that interpolated a PR title into `run:`, and its malicious npm releases harvested over 2,000 secrets and drove victims' local Claude, Gemini and Q CLIs with permission-bypass flags ([Nx](https://github.com/nrwl/nx/security/advisories/GHSA-cxm3-wv7p-598c); [Wiz](https://www.wiz.io/blog/s1ngularitys-aftermath)). GhostAction pushed a workflow that sent 3,325 secrets to an attacker, after which PyPI recommended Trusted Publishers ([GitGuardian](https://blog.gitguardian.com/ghostaction-campaign-3-325-secrets-stolen/)). TeamPCP rewrote existing `trivy-action` tags, and the unpinned scanner in LiteLLM's CI harvested its PyPI token, producing releases that ran malicious code at every Python startup ([The Register](https://www.theregister.com/2026/03/24/trivy_compromise_litellm/)). An over-scoped CI token let an attacker ship a wiper prompt inside an Amazon Q release ([AWS](https://aws.amazon.com/security/security-bulletins/AWS-2025-015/)). Guild already plans SHA pins and steward-approved releases, and confusable's roadmap names Trusted Publishing; the additions are no cache restores in any publish or secret-bearing workflow, a publish job that only uploads an artifact built in another job, GitHub's organisation-level SHA-pinning policy ([GitHub changelog](https://github.blog/changelog/2025-08-15-github-actions-policy-now-supports-blocking-and-sha-pinning-actions/)), and zizmor's audits for cache poisoning, unpinned tools and Trusted Publishing ([zizmor](https://docs.zizmor.sh/audits/)).

## No published precedent lets agent code merge without a human

Open-source policy has settled on one rule: a human who understands a change is accountable for it, and agents neither submit nor approve on their own. LLVM bans agents that act in project spaces without human approval and automated review comments posted without human review, with one council-approved bot exception ([LLVM](https://llvm.org/docs/AIToolPolicy.html)). The kernel says "The AI assistant must never send anything itself" and that only humans sign the Developer Certificate of Origin ([kernel](https://docs.kernel.org/process/coding-assistants.html)). Fedora says AI must not be the "sole or final arbiter" in review ([Fedora](https://forge.fedoraproject.org/council/docs/commit/823e93b640dea2205d6df2bc51586552a52898d7)), and Mesa requires a human to open each merge request ([Phoronix](https://www.phoronix.com/news/Mesa-Two-Gen-AI-Policies), secondary). The platforms encode the same rule. A requester cannot approve a Copilot agent PR, and a PR the agent opens under its own identity needs one extra approval ([GitHub Docs](https://docs.github.com/en/copilot/concepts/agents/coding-agent/risks-and-mitigations)). The only mainstream way for an AI approval to count, Copilot code review approvals, entered public preview on 1 September 2026, off by default, limited to file paths an admin chooses, and dismissed on any new push ([GitHub changelog](https://github.blog/changelog/2026-09-01-copilot-code-review-can-now-approve-pull-requests)). Among large organisations only OpenAI's agent-only team, building an internal beta product, does most human review after merge, and it still gates release promotion on a human-approved smoke test ([Latent Space](https://latent.space/p/harness-eng)); Spotify describes auto-merge only as "potential" for documentation ([InfoQ](https://www.infoq.com/news/2026/03/spotify-honk-rewrite/)).

The evidence explains the caution. METR had four maintainers of scikit-learn, Sphinx and pytest blind-review 296 agent PRs that had passed SWE-bench Verified; normalised to the 68% at which they re-approved the original human patches, **their merge rate was 24.2 points below the automated grader**, so roughly half of test-passing patches were unmergeable ([METR](https://metr.org/notes/2026-03-10-many-swe-bench-passing-prs-would-not-be-merged-into-main/)). AI review is weakest where a small library lives: Anthropic says its own Code Review finds something in only **31% of PRs under 50 lines** ([Claude blog](https://claude.com/blog/code-review)), so a silent Reviewer says little, and a small independent study saw reviewer F1 fall from 0.657 on diffs under 10 lines to 0.043 over 150 lines, with a best F1 on real PRs of 0.066 ([arXiv 2606.15689](https://arxiv.org/abs/2606.15689)). Security-related agent PRs merge less often (61.5% against 77.3%) and wait far longer for review ([arXiv 2601.00477](https://arxiv.org/html/2601.00477v1)), and flawed security PRs, including inefficient regular expressions, still get merged ([EASE 2026](https://conf.researchr.org/details/ease-2026/ease-2026-research-papers/13/Insights-into-Security-Related-AI-Generated-Pull-Requests)). Nearly every code path in confusable is security-relevant, so T0 should be limited to the categories with the highest independent acceptance, documentation and chores at 82-84% ([arXiv 2602.08915](https://arxiv.org/html/2602.08915)), excluding anything agents read as instructions, and every code change should need at least one steward. confusable's ICU and Rust oracle fixtures make T1 unusually defensible for oracle-covered code. They do not make T0 defensible, because the failure the field fears most, in Spotify's ranking, is a PR that "passes CI but is functionally wrong" ([Spotify](https://engineering.atspotify.com/2025/12/feedback-loops-background-coding-agents-part-3)).

Guild's deterministic path tiers are the right mechanism, and GitHub now lets them be enforced server-side: the required-reviewer rule, generally available since 17 February 2026, demands approvals from named teams for specific paths ([GitHub changelog](https://github.blog/changelog/2026-02-17-required-reviewer-rule-is-now-generally-available/)). Mirroring T1-T3 in rulesets means a bug or an agent edit in Guild's tier script cannot downgrade a change, and a CI check that fails when the tier code and the ruleset disagree keeps them aligned. Paths alone are not enough. An MSR 2026 study found maintainers auto-merge smaller agent PRs and grow cautious when a PR deletes code ([MSR](https://2026.msrconf.org/details/msr-2026-mining-challenge/61/LGTM-Characteristics-of-Auto-Merged-LLM-based-Agentic-PRs)), so diff size, deletions, dependency or lockfile changes, build configuration and test edits should be inputs that can only raise a tier. Merge logs hide who actually decided ([arXiv 2605.08017](https://arxiv.org/pdf/2605.08017)), so each merge needs a decision record naming the tier, policy version, approvers, and model and CLI versions. SLSA's two-party review counts trusted persons ([SLSA](https://slsa.dev/spec/v1.2/verified-properties)), so T0 merges and T2 merges made by one steward plus a 24-hour wait should both be recorded as single-review. A wait adds safety only if someone else can look during it; a public "merging in 24 hours" label and a fresh steward read after the delay turn it into a notice period. With one steward today, **T3 cannot be satisfied at all**, so Guild must say whether the first release and any security advisory wait for a second steward or follow a defined fallback, since a late advisory is a risk too. The same applies to GitHub's requester-is-not-approver rule: when the only steward issues the command that starts a Builder run and then approves its PR, Guild should say so and record it.

The binding constraint is steward attention, not agent capacity. Every organisation in the first section reports review as its bottleneck, and the human side degrades. Among 400 repeat reviewers of agent PRs, approval rates rose while inline comments fell 22% and words 28% over about seven months, which the authors read as habituation under workload rather than earned trust ([Emergent Mind summary](https://www.emergentmind.com/papers/2606.22721), observational). At Vercel a human approved a change the risk classifier had correctly flagged as high risk, and it caused an incident ([Vercel](https://vercel.com/blog/58-percent-of-prs-in-our-largest-monorepo-merge-without-human-review), vendor). Anthropic's own randomised trial found AI-assisted engineers scored about 17% lower on comprehension of the code they had just worked with ([Anthropic](https://www.anthropic.com/research/AI-assistance-coding-skills), vendor-run, 52 mostly junior engineers). Guild therefore needs a cap on agent PRs awaiting review, a steward approval of the plan before the Builder spends budget on T2 and T3 work (Google's Jules waits for plan approval ([Jules](https://jules.google/docs/changelog/2025-08-083)), and a short structured plan is cheaper to review than a wrong PR), metrics on the stewards' own scrutiny (comments per review, time on review, approval drift), periodic seeded-defect checks of stewards as well as the Reviewer, and some steward-written work to keep their grasp of the code. Jazzband's shutdown after its open model became a one-person operation ([Jazzband](https://jazzband.co/news/2026/03/14/sunsetting-jazzband)) is the bus-factor version of the same risk.

Closing the code path to outsiders is mainstream. GitHub added a setting restricting PR creation to collaborators on 13 February 2026, and Dependabot still counts as a collaborator under it ([GitHub changelog](https://github.blog/changelog/2026-02-13-new-repository-settings-for-configuring-pull-request-access/); [discussion #187038](https://github.com/orgs/community/discussions/187038)). Ladybird, openai/codex and tldraw closed outside PRs while keeping reports open ([Ladybird](https://ladybird.org/posts/changing-how-we-develop-ladybird/)), and openai/codex's announcement drew 56 thumbs-up to 15 down ([openai/codex](https://github.com/openai/codex/discussions/9956)). Whether a GitHub App that is not a collaborator can still open PRs under that setting is undocumented, so Guild must test its Builder App against it. Closing PRs moves the flood to issues. curl reports that since spring 2026 slop has given way to "high volume, high quality": hundreds of AI-assisted vulnerability reports, with reproducers that take "a prompt or two" ([Stenberg](https://daniel.haxx.se/blog/2026/10/22/ignore-the-slop/)). tldraw described an "AI self-loop" in which agent-drafted issues about nonexistent bugs became agent PRs ([tldraw](https://tldraw.dev/blog/stay-away-from-my-trash)). GitHub's issue restriction is all-or-nothing and would break Guild's model, so Guild needs a flood playbook built on temporary interaction limits instead ([GitHub REST](https://docs.github.com/en/rest/interactions/orgs)).

Pillar 5 lines up with the strictest projects. The kernel wants a reproducer before a report, CPython says changing tests to make a failing test pass is "not a real fix" ([devguide](https://devguide.python.org/getting-started/ai-tools/)), and Django closes unverified reports and bans fabricated references ([Django](https://docs.djangoproject.com/en/dev/internals/contributing/writing-code/submitting-patches)). curl's experience changes what a failing test filters: it stops hallucinated bugs, not volume. **The oracle citation is the stronger filter because it can be checked mechanically**: a deterministic job can run the reported code points through the committed ICU and Rust fixtures, or the oracles themselves, and confirm the claimed expected value before any model or steward spends time. The failing test should also arrive as data rather than code. A Python test pasted into an issue is untrusted code, and if the Builder copies it into `tests/` it runs in CI; an issue form that asks for code points, the function called, expected and actual results and the specification clause lets a script generate a parametrised test, which closes that path and keeps the Builder away from raw issue text. That is an inference from the incidents above, not a published practice. For features, LLVM's "extractive" label, for contributions whose review cost exceeds their value, is a precedent for judging requests against charter clauses, and Spec Kit's gates are a precedent for enforcing them, though no study shows either improves outcomes.

The community-facing parts need small adjustments. Seth Larson, who triages security reports for CPython, pip, urllib3 and Requests, supports closing reports whose authors do not respond but warns that public credit is an incentive for slop ([Larson](https://sethmlarson.dev/slop-security-reports)), so credit should follow a validated report. A study of 20 large projects found Stale bot sped up closure but was followed by a notable drop in active contributors ([arXiv 2305.18150](https://web3.arxiv.org/abs/2305.18150?context=cs), 2023), so the 21-day close should apply only to missing information, name exactly what is missing, and reopen on one comment. Django, Ghostty, LLVM and Mesa ask contributors to disclose AI use, and Stenberg wants a short human summary ahead of long AI reports; both are cheap additions to an issue form. Provenance needs a named human. Purely AI-generated material is not copyrightable in the US ([Copyright Office](https://www.copyright.gov/ai/)), the Supreme Court declined to revisit that on 2 March 2026 ([Mayer Brown](https://www.mayerbrown.com/en/insights/publications/2026/03/supreme-court-denies-review-in-ai-authorship-case)), and the ASF puts the burden of third-party material on the contributor ([ASF](https://www.apache.org/legal/generative-tooling.html)). For confusable the merging steward is the certifier, agent commits should carry an `Assisted-by` or `Co-authored-by` trailer and be signed by the App, and agents should work from the Unicode specifications rather than ICU's or the Rust crate's source, so they do not reproduce code under another license.

## Caps, drills and pins are softer than they look

Guild's drills follow Anthropic's eval guidance, which recommends starting with 20-50 tasks drawn from real failures and keeping a regression suite near 100% ([Anthropic](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)). Three statistical details decide whether the gate works. Single trials are noisy: with model, harness and tasks fixed, Anthropic measured a **6-point spread on Terminal-Bench 2.0 between container configurations alone** ([Anthropic](https://www.anthropic.com/engineering/infrastructure-noise)). Consistency compounds: at 75% per-trial success the chance that three trials all pass is about 42%, and consistency is what an auto-merge path needs. And small suites are blunt: 30 drills run three times give 90 trials, and at an 80% pass rate the 95% interval is roughly plus or minus 8 points (my arithmetic). "No quality drop" must therefore be a threshold above measured noise, computed on paired runs of the same drills with fixed runner sizes and timeouts, or the gate will either block constantly or be ignored.

Replaying confusable's own public history adds two traps. Models memorise public fixes: OpenAI stopped reporting SWE-bench Verified in February 2026, citing contamination and flawed tasks in 59.4% of 138 audited hard problems ([OpenAI](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/); figures from a search summary because the page returned HTTP 403), and on SWE-rebench GPT-4.1 dropped from 31.1% to 26.7% on newer tasks ([arXiv 2505.20411](https://arxiv.org/pdf/2505.20411)). And the answer sits in the repository: Anthropic's own example of eval leakage is Claude reading the git history of earlier trials. Drills must strip later commits, tags, remote refs and the PR thread, keep a bucket of issues created after each candidate model's training cutoff that carries the deciding weight, and keep some drills private. Grading should check outcomes rather than match the historical diff: the original tests, a rubric built from METR's rejection reasons (code quality, breaking other code, core functionality), cost and turns. The suite also needs negative drills where the right answer is "needs info", "close" or "do nothing", and a separate capability suite that starts at a low pass rate and measures headroom for upgrades. Anthropic's CORE-Bench score moved from 42% to about 95% after fixing graders and tasks, which is why the monthly retrospective should read transcripts, not only pass counts.

Pinning the model is necessary and not enough. Anthropic's 23 April 2026 postmortem traced a quality drop to three Claude Code product changes with the API and models unchanged: a default effort cut from high to medium, a thinking-cleanup bug that ran on every turn, and a system-prompt line limiting verbosity. "Neither our internal usage nor evals initially reproduced the issues", and the remedies promised soak periods and gradual rollouts ([Anthropic](https://www.anthropic.com/engineering/april-23-postmortem)). In August and September 2025, serving-side bugs degraded responses from pinned models ([Anthropic](https://www.anthropic.com/engineering/a-postmortem-of-three-recent-issues)). Guild's pinned state should therefore include the CLI version, effort level, settings and plugin version as well as the model ID, each gated by drills and followed by a soak period, with a weekly canary drill between changes, since a monthly retrospective is a long detection window. One interaction needs fixing before Guild exists: **confusable's Dependabot workflow auto-merges non-major updates, GitHub Actions included** (`.github/workflows/dependabot-auto-merge.yml`), so a `claude-code-action` bump would bypass the drill gate unless it is excluded. Model IDs need care across providers. Claude Code's aliases move and resolve differently by provider (`sonnet` is Sonnet 5.5 on the Anthropic API but Sonnet 4.5 on Bedrock and Vertex), default effort differs by model, and unsupported effort levels fall back silently ([model configuration](https://code.claude.com/docs/en/model-config)). Pinned models also expire: Anthropic gives at least 60 days' notice, Sonnet 4 was deprecated in April and retired in June 2026, Sonnet 4.5 retires on 30 November 2026, and Bedrock and Vertex set their own schedules ([deprecations](https://platform.claude.com/docs/en/about-claude/model-deprecations)). A weekly workflow that opens an issue when a pinned model is deprecated, modelled on confusable's `unicode-release.yml` and listed in the `scheduled` job as AGENTS.md requires, turns migration into routine work.

The per-run cap is soft. Claude Code computes `total_cost_usd` locally from token counts at list price, the same estimate feeds `--max-budget-usd`, the docs warn "Spend can pass the cap, so leave headroom", spend from resumed sessions is not counted, and `--max-turns` has no default limit ([CLI reference](https://code.claude.com/docs/en/cli-reference.md); [costs](https://code.claude.com/docs/en/costs)). One independent test set a $0.01 cap and **spent $0.0844 in a single turn** before the check fired ([LinuxJedi](https://linuxjedi.co.uk/when-the-docs-fall-short-investigating-claude-codes-budget-cap/)). The only hard stop is the provider's. Console workspace limits are monthly and enforced server-side, but CI needs an API key and the workspace Claude Code creates automatically cannot issue API keys, so Guild needs a dedicated workspace, configured in the Console because the spend-limit API is an early-access preview ([spend limits](https://platform.claude.com/docs/en/api/http/beta/organization/spend_limits/set.md)). Hitting that cap stops triage along with everything else, so it doubles as a kill switch and needs a defined failure message. The research found no evidence of an equivalent provider-enforced cap on Bedrock or Vertex, so that part of the portability promise is unverified. The caps should form a hierarchy: per run, a budget sized to leave one maximal turn of headroom, `--max-turns` and a job `timeout-minutes`; per day, an alert computed from the ledger; per month, the workspace limit. A PreToolUse hook that aborts after repeated identical tool calls addresses the runaway loops users report ([Cursor forum](https://forum.cursor.com/t/agent-enters-infinite-loop-re-reading-the-exact-same-file-range-with-auto-mode/170975)), and the ledger should be reconciled monthly against billed usage.

Prompt caching shapes the numbers more than routing does. Cache reads cost a tenth of base input (a twentieth on the 5.5 models), five-minute cache writes cost 1.25x, changing tool definitions invalidates the whole cache, and changing effort invalidates the message history ([prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)); Anthropic's example session shows 940,000 cache-read tokens against 1,200 uncached. A skill or tool edit can therefore move cost without moving quality, which drills should expose by reporting cache reads and writes separately, and drills run back to back inside the five-minute window will understate what sporadic real issues pay. Learned routing cut costs sharply on chat benchmarks in 2024 ([LMSYS](https://lmsys.org/blog/2024-07-01-routellm/)), but a 2025 re-evaluation found routers sent every code query to the strong model ([arXiv 2504.07113](https://arxiv.org/pdf/2504.07113)). Guild's static routing by role is unvalidated; OpenAI's advice is to baseline every role on the most capable model and move to smaller ones only under evals ([OpenAI](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)), and one small study found Haiku 4.5 out-reviewing Sonnet 4.6 at a third of the cost ([arXiv 2606.15689](https://arxiv.org/abs/2606.15689)). The two-attempt rule can become a cascade, escalating the model rather than repeating it on the second Builder attempt ([arXiv 2405.15842](https://arxiv.org/abs/2405.15842v1)). No published method orders a backlog by value per expected cost, so Guild should compare its predictions with `total_cost_usd` and outcomes before trusting the ordering. The ledger should record who decided as well as what it cost, avoid the OpenTelemetry GenAI conventions while every attribute is still marked "Development" ([Dash0](https://www.dash0.com/knowledge/opentelemetry-genai-semantic-conventions-explained)), contain no model free text, and be append-only by ruleset, because public repositories have public logs.

Two of these verdicts rest on arithmetic rather than literature. A two-week shadow phase on a small library yields perhaps tens of decisions, and zero bad merges in n decisions bounds the bad-merge rate only below about 3/n at 95% confidence, so 20 clean decisions rule out rates above 15% and about 60 are needed to reach 5%. Shadow mode for T0 should end on a count, combined with drill evidence, and may take months. The "no beta-only features" rule is sound and worth applying deliberately: GitHub Agentic Workflows (public preview since June 2026), Copilot code review approvals (public preview), Anthropic's managed Code Review (research preview, unavailable to Bedrock- or Vertex-only organisations), Claude Code agent teams (experimental) and the spend-limit API (early access) all offer patterns to copy, not dependencies to take.

## Conclusion

The research moves Guild's risk from where its design spent the most care. Quarantined triage deserves that care, but the expensive failures in 2025-2026 happened where one agent's output became something else's input: a cache entry a release restored, a `conftest.py` that CI ran, a config file the next headless session loaded, a PR description the Reviewer read. Guild's governing invariant should be that **nothing a model wrote is executed or obeyed with more privilege than the model had, until a deterministic check or a steward has passed it**. That is the stance confusable already takes toward its data, where the test suite is the product and generated tables are never edited by hand, extended to agents, and it makes the deterministic shell rather than the agents the part of Guild worth reusing across repositories.

The second shift is that Guild's scarce resource is human and its evidence will have to be its own. Every team that scaled agents found review, not generation, was the bottleneck, and the independent data says human review quietly weakens as agent volume rises; a three-steward project that measures the Reviewer's catch rate but not the stewards' is watching the wrong gauge. Because no independent study has tested a pipeline like Guild's on a real library, the ledger, drills and shadow decisions are more than operations. Published openly, they would be among the first auditable evidence on whether agent-run maintenance of a security library works, which is a stronger reason to keep them rigorous than any single control.
