## 1. GitHub Copilot coding agent ("Copilot cloud agent"), Agent HQ / mission control: assignment, sandbox, firewall, branches, approvals, custom agents, metrics

### Takeaway
GitHub's own agent is built on the premise that the agent is an untrusted outside contributor: it can push only to one fresh `copilot/` branch, cannot approve, mark ready, or merge, its CI does not run until a human with write access clicks approve (opt-out added March 2026), the human who asked for it cannot be the approving reviewer, and PRs opened under the agent's own identity need one extra approval. GitHub only began letting an AI review count toward required approvals in September 2026, off by default and scoped by file path, which is the closest platform analogue to Guild's T0.

### Inferences
- GitHub's defaults encode three rules Guild partly lacks: (a) agent-authored code is outside-contributor code, so its CI needs a human approval or a secret-free sandbox; (b) the person or system that requested a change cannot be the one who approves it; (c) agent-only PRs need more approvals, not fewer. Guild's T0 inverts (c). The only platform-sanctioned route to zero-human merges is Copilot code review approval (Sept 2026, preview, default off, path-scoped), which suggests T0 should be path-scoped, opt-in per path, and dismissed on any new push. All of those are deterministic properties Guild can copy.
- The Copilot firewall's documented blind spots (MCP servers, setup steps) suggest Guild should not rely on a tool-level allowlist alone; runner-level egress control is the stronger form.
- Hidden-character filtering is standard input hygiene on all three vendor stacks (GitHub, claude-code-action, and see below); confusable's own detectors are a natural fit for Guild's Triage pre-filter.

### Gaps
- No GitHub-published count or merge rate for PRs authored by Copilot coding/cloud agent was found (searched Octoverse and changelogs).
- The launch date of the "additional approval for unattributed Copilot PRs" rule was not found; the docs page that states it is undated.
- Whether a Copilot code review approval may count on a Copilot-cloud-agent-authored PR (self-review by the same vendor) is not stated.
- Current (post-June-2026) Copilot billing model not confirmed from a primary source.

## 2. Other commercial agent platforms: OpenAI Codex, Google Jules, Cognition Devin, Factory, Amp, Cursor, Anthropic Claude Code (Actions, cloud, Code Review)

### Takeaway
Every vendor stops short of letting its agent merge by default: Codex, Cursor, Devin and Claude Code open branches or PRs and leave merging to humans; review bots (Codex review, Bugbot, Devin Review, Anthropic Code Review, Copilot review) explicitly do not approve, except Copilot's new opt-in approval. Defaults differ sharply on network (Codex blocks agent-phase internet; Cursor allows all; Claude Code cloud allows a "Trusted" list that includes GitHub). Cost control is per-run turn/budget/time caps plus org-level monthly caps. The official Claude GitHub App is broadly privileged, and Anthropic's own docs recommend a custom App with only Contents/Issues/Pull requests for the Action.

### Inferences
- Vendor defaults cluster into "agent proposes, human disposes". The only places where merges happen without a human are internal (OpenAI harness team) or the new, opt-in Copilot approval. Guild's T0 sits at the aggressive end of published practice; the published practice that supports it relies on fast human post-merge review and a human-gated release, which Guild's T3 provides.

## 3. Internal agent platforms and case studies: Stripe, Shopify, Spotify, Uber, Block, Airbnb, Google, Meta, Coinbase, Ramp, Rakuten, Anthropic

### Takeaway
The large internal platforms (Stripe Minions, Spotify Honk, Ramp Inspect, Block BuilderBot, Uber Minion, OpenAI's harness team) converge on: an ephemeral pre-warmed sandbox cut off from production; deterministic steps (lint, test, push, PR creation) wrapped around a narrow agent step; a hard cap on fix iterations; PR creation only after verification; and human review of every PR. The one place auto-merge is mentioned (Spotify, docs changes) is described as "potential". Reported agent share of merged PRs ranges from ~11% (Uber) and ~15% (Block) to ~50-75% (Ramp), all self-reported. Every team now names review, not generation, as the bottleneck, and at least one (Spotify) saw agents weaken tests to pass CI.

### Inferences
- The strongest common denominator across Stripe, Spotify, Ramp, Block and OpenAI is not "required human review" (OpenAI is the exception) but "a deterministic harness owns every side effect": the agent edits files; code outside the agent runs lint/tests, pushes, opens PRs and enforces iteration limits. Guild's three Apps give agents tokens directly; the published designs suggest the token should be held by the deterministic wrapper, with the agent returning a diff or a structured request (GitHub's safe-outputs pattern, Spotify's infra-pushes pattern).
- Spotify's sequence (LLM judge vetoes 25% in Dec 2025, removed as too rigid by Mar 2026) and its observed test-weakening shortcuts argue that Guild's T0 should rest on deterministic checks (no test deletions/skips/xfail additions, coverage non-decrease, no changes to generated tables or fixtures, ASCII-source hygiene) with the Reviewer as an additional, not sole, gate.
- The named reason most orgs keep humans in the loop is functional wrongness that passes CI. For confusable, the conformance fixtures from ICU and Rust are an unusually strong oracle, which makes T0 more defensible here than in a typical product codebase, but only for changes the oracles cover.
- Review capacity is the universal bottleneck. With <=3 stewards, Guild's throughput will be bounded by T1/T2 review time, not Builder speed, so a Planner that keeps PRs small and an inbox/priority mechanism (Spotify, Uber) matter more than Builder parallelism.

### Gaps
- No case study states an agent PR auto-merge policy in production for a security-sensitive or published library. The closest are OpenAI's internal beta product (post-merge human review) and Spotify's "potential" docs-only auto-merge.
- Stripe Minions Part 2 (implementation, "blueprints") was not found; no Stripe cost-per-run or merge-after-review rate is public.
- Block BuilderBot review/merge policy and Uber Minion details (paywalled) not retrieved; Meta has no primary data.
- No org publishes its kill-switch design or incident post-mortems for agent-merged regressions.

## 4. Patterns the industry converges on (task scoping, plan before code, ephemeral sandboxes, review, CI as gate, separate review agents, kill switches, phased rollout)

### Takeaway
Convergent patterns with strong support: small, verifiable tasks; deterministic harness around a narrow agent step; ephemeral sandboxes with no production access; verification before PR creation; capped retry loops; a separate review agent on every PR; human approval of every merge (with very few exceptions); hidden-character stripping and write-access gating of triggers. Weakly supported or unpublished: different-model review, kill switches, budget ledgers, post-merge audit sweeps.

### Cited Findings
- Task scoping: Devin works best on "clear upfront requirements and verifiable outcomes" of 4-8 junior-engineer hours (2025-11-14); Cognition: "success scales with specificity", split large work into isolated sessions (2026-02-27); Shopify: AI roaming freely "didn't work very well", break work into small steps (2025); Stripe aims to one-shot, with feedback loops as fallback (2026-02-09); security PRs that are larger/longer-titled are rejected more (2026-01-01). -- [Cognition review](https://cognition.com/blog/devin-annual-performance-review-2025); [Cognition on Devin](https://cognition.com/blog/how-cognition-uses-devin-to-build-devin); [Shopify Roast](https://shopify.engineering/introducing-roast); [Stripe Minions](https://stripe.dev/blog/minions-stripes-one-shot-end-to-end-coding-agents); [arXiv 2601.00477](https://arxiv.org/html/2601.00477v1) [Guild: SUPPORTS Planner producing small, single-purpose tasks]
- Plan before code: Jules waits for plan approval (2025); Anthropic security engineers ask for pseudocode first (2025-07-24); Claude Code docs: "Plan locally, execute in the cloud" using plan mode, commit the plan, then run autonomously (undated, retrieved 2026-10-26); Spotify uses an interactive agent to gather task details before handing a prompt to the coding agent (2025-11-06). -- [Jules changelog](https://jules.google/docs/changelog/2025-08-083); [Claude blog](https://claude.com/blog/how-anthropic-teams-use-claude-code); [Claude Code cloud docs](https://code.claude.com/docs/en/claude-code-on-the-web); [Spotify part 1](https://engineering.atspotify.com/2025/11/spotifys-background-coding-agent-part-1) [Guild: SUPPORTS Planner role; MISSING a human checkpoint on plans for T2/T3 before Builder spends budget]

- Requester != approver, and the agent never merges: Copilot docs (undated); claude-code-action leaves PR creation to the human in `@claude` mode (undated); Stripe requires "another Stripe engineer" (2026-02-09). -- sources above [Guild: SUPPORTS for T1+; CONTRADICTS T0]

### Inferences
- Guild's design already matches most convergent patterns (roles, small tasks, ephemeral Actions runners, agent review, CI gate, cost caps). Where it diverges from the field: (1) T0 merges with no human; (2) agents hold App tokens directly rather than handing results to a deterministic writer; (3) no stated egress control; (4) no stated input sanitisation for Triage; (5) no stated kill switch or phased rollout; (6) CI on agent PRs runs agent-written code with no approval gate.
- "Agents cannot change CI/agent config" matches the vendor mechanism (claude-code-action restores `.claude/`, `CLAUDE.md`, `.mcp.json` from base), but the field's experience is that the attack surface is wider: anything executed during tests or hooks (in this repo: `pyproject.toml`, `conftest.py`, `tests/**`, `tools/**`, `.pre-commit-config.yaml`, `uv.lock`) is effectively CI config when run.

### Gaps
- No published comparison of same-model vs different-model author/reviewer pairs on agent PRs.
- No public post-mortem of an agent auto-merged regression in a production repo found.
- No organisation publishes how it reconciles per-run agent cost caps with billed usage.

## 5. Published metrics on acceptance and merge rates of agent PRs (GitHub data, academic studies, vendor numbers)

### Takeaway
Independent studies on public GitHub data (AIDev, 2025-2026) put agent PR acceptance at roughly 60-80% depending on agent and task, with docs/chore/CI changes highest (75-84%) and fixes, tests and performance lowest (55-66%); security-related agent PRs merge less often (61.5% vs 77.3%) and wait far longer for review. Acceptance is not correctness: METR found about half of test-passing agent patches would not be merged by maintainers, and an EASE 2026 study found flawed security PRs still get merged. Vendor numbers (Devin 67%) run above independent ones for the same agent.

### Cited Findings
- AIDev dataset (Li, Zhang, Hassan; arXiv 2025-07-20): >456,000 PRs by OpenAI Codex, Devin, GitHub Copilot, Cursor and Claude Code across 61,000 repos and 47,000 developers; agent PRs "are accepted less frequently" than human PRs (a "trust and utility gap"); agents are faster and their PRs "structurally simpler"; one developer submitted as many PRs in three days as in the previous three years. Later releases are larger (932,791 PRs per one follow-up); the curated AIDev-pop subset (~33,596 PRs) is defined as >=500 stars in the original paper but >=100 stars in several follow-ups. -- [arXiv 2507.15003](https://arxiv.org/abs/2507.15003); [arXiv 2601.18749](https://arxiv.org/html/2601.18749v1) [Guild: CONTEXT]
- Task-stratified acceptance (Pinna, Gong, Williams, Sarro; MSR '26, arXiv 2602.08915 v2 2026-05-07; 7,156 closed PRs from permissively licensed 100+ star repos with at least one non-author review/comment): Codex 77.9% (2,002 PRs), Cursor 74.5% (569), Claude Code 71.9% (139, small sample), Copilot 68.0% (2,194), Devin 61.6% (2,252); overall 69.3%. By task: chore 84.0%, docs 82.1%, style 78.1%, ci 75.0%, build 72.5%, refactor 71.2%, feat 66.1%, fix 66.0%, test 61.5%, revert 60.0%, perf 55.4%. Codex ranged 59.6% (test) to 88.6% (chore). Devin was the only agent with a consistent upward trend (+0.77 pp/week over 32 weeks). Copilot PRs received 4.94 reviews/PR vs 1.39 for Codex. Only 6 of 64 pairwise task-stratified comparisons passed Bonferroni. Authors: acceptance is not quality; observational; repository clustering not modelled. -- [arXiv 2602.08915](https://arxiv.org/html/2602.08915) [Guild: SUPPORTS T0 for docs/chore/ci-like low-risk categories as the first auto-merge class; tests and fixes are where agents are rejected most]
- Security-related agentic PRs (Siddiq et al., Notre Dame; arXiv 2601.00477, 2026-01-01; AIDev curated 33,596 PRs, 1,293 confirmed security-related = 3.85%): merged 61.50% vs 77.33% for non-security; median review latency 3.92 h vs 0.11 h (means 97.45 h vs 38.29 h); security merge rates by agent: Codex 86.59%, Cursor 76.47%, Claude Code 58.62%, Devin 52.12%, Copilot 49.60%; of 1,130 closed security PRs 38.5% rejected; rejection associated with longer titles and larger PRs (mean 2,720 vs 1,873 changed lines); agents mostly do "supportive hardening" (tests, docs, config, error handling) rather than targeted vulnerability fixes. -- [arXiv 2601.00477](https://arxiv.org/html/2601.00477v1) [Guild: SUPPORTS putting security-relevant changes at T2+; confusable is a security library, so most non-doc changes are security-relevant by this definition]
- Flawed security PRs merged (Hasan, Rabbi, Zibran; EASE 2026; 675 security-related PRs of 33,596): recurring weaknesses include regex inefficiencies, injection flaws and path traversal; "many flawed PRs still get merged", while rejections often come from process issues (inactivity, missing tests). -- [EASE 2026 listing](https://conf.researchr.org/details/ease-2026/ease-2026-research-papers/13/Insights-into-Security-Related-AI-Generated-Pull-Requests) [Guild: CONTRADICTS "merged = correct"; regex inefficiency (ReDoS-like) is directly relevant to a text-processing library and is the kind of defect CI rarely catches; MISSING performance/complexity checks for T0]
- Claude Code PRs in the wild (Watanabe, Li, Kashiwa, Reid, Iida, Hassan; arXiv 2509.14745, accepted at ACM TOSEM; 567 PRs across 157 projects): 83.8% eventually merged; of merged PRs, 54.9% went in unmodified and 45.1% needed human revisions (bug fixes, docs, project-specific standards); mostly refactoring, docs and tests. v1 reported human PRs at ~91% acceptance (framing not confirmed in v3). -- [arXiv 2509.14745](https://arxiv.org/html/2509.14745v3) [Guild: SUPPORTS T1 as the default for code; nearly half of merged agent PRs needed a human touch]
- METR (2026-03-10): four active maintainers of scikit-learn, Sphinx and pytest reviewed 296 AI-generated PRs from five models (Claude 3.5 Sonnet to Claude 4.5 Sonnet, GPT-5); "roughly half of test-passing SWE-bench Verified PRs written by mid-2024 to mid/late-2025 agents would not be merged into main by repo maintainers", after adjusting for noise; the human-written reference patches were themselves re-approved only 68% of the time; agents could not iterate on feedback, so METR does not claim a capability ceiling. -- [METR note](https://metr.org/notes/2026-03-10-many-swe-bench-passing-prs-would-not-be-merged-into-main/) [Guild: CONTRADICTS "CI passing + agent review" as a sufficient gate for code changes in a Python library maintained to a high standard (pytest/sphinx/scikit-learn are close analogues); supports keeping T0 narrow]
- Merge-outcome drivers (arXiv 2601.18749, 2026-01; 6,618 human vs 33,596 agentic PRs): submitter attributes dominate merge outcomes for both groups, while review-related features have contrasting effects between human and agentic PRs. -- [arXiv 2601.18749](https://arxiv.org/html/2601.18749v1) [Guild: CONTEXT; acceptance rates partly measure who is submitting (many agent PRs are opened and merged by the same developer)]
- Mobile repos (arXiv 2602.12144, 2026-02): Android projects received 2x more AI-authored PRs and higher acceptance (71%) than iOS (63%). -- [arXiv 2602.12144](https://www.arxiv.org/abs/2602.12144) [Guild: CONTEXT]
- Newer longitudinal study (Mazloomzadeh, Morovati, Khomh; arXiv 2607.21832, 2026-07-23): compares agentic and human PRs on quality-relevant characteristics and their change over time on AIDev; a secondary summary reports Devin's estimated merge probability at 43.0%, the lowest of the agents studied (figures not verified from the paper). -- [arXiv 2607.21832](https://arxiv.org/abs/2607.21832); [agentmarketcap (secondary)](https://agentmarketcap.ai/blog/2026/08/26/cognition-devin-67-percent-pr-merge-rate-vendor-production-metric) [Guild: CONTEXT]
- Vendor-reported rates for comparison: Devin 67% merged (2025-11-14, defined by Cognition, includes PRs merged after rework per secondary critique); Cursor Bugbot resolution 52% -> >70% (2026-01-15), ~80% (2026-05, secondary); Anthropic Code Review <1% findings judged incorrect (2026-03-09); OpenAI engineers merge 70% more PRs/week (2025-10). -- sources in sections 2 and 3 [Guild: CONTEXT; vendor metrics define their own denominators]

### Inferences
- The acceptance hierarchy (chore/docs/ci > refactor > feat/fix > test > perf) gives an empirical basis for Guild's deterministic tiering by change type and path: docs-only and metadata-only changes are the defensible T0 class; anything touching `src/confusable/` logic, generated data, fixtures or the attack corpus should be T1 or above.
- High AIDev acceptance for Codex coincides with very low review counts (1.39 reviews/PR) and, for non-security PRs, a 0.11 h median review latency, which suggests many such PRs are self-merged by the developer who ran the agent. Public "acceptance" therefore overstates independent approval; it is not evidence that agent review can replace human review.
- METR's 68% re-approval of human reference patches shows maintainer judgement itself is noisy; a Guild ledger that records steward overrides and post-merge reverts would give confusable its own base rates rather than borrowing these.

### Gaps
- No study isolates PRs that were merged with only an AI approval (no human approval), so there is no published defect or revert rate for auto-merged agent PRs.
- No study measures post-merge revert or bug rates of agent PRs vs human PRs on comparable tasks (AIDev papers measure acceptance and latency, not downstream defects).
- A third-party tracker claim that only 2.9% of merged agent-marked public PRs had any GitHub review record before merge (surfaced via search, source edge.amplifying.ai) could not be verified and is excluded from findings.
- GitHub has not published merge rates for Copilot cloud agent PRs; Anthropic, OpenAI and Google have not published merge rates for their agents' PRs on public GitHub.
